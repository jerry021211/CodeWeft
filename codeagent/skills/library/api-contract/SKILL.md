# API 契约

先对照路由、请求与响应模型、客户端类型以及已有接口测试。记录字段的必填性、可空性、默认值和序列化名称，区分缺失字段与显式 null。

沿正常、无效输入、资源不存在三个路径核对状态码和响应形状。关注分页边界、空集合、错误结构和旧客户端兼容性。异步任务接口还需区分接收成功与任务完成。

修改时同步影响到的客户端和契约测试；不自行扩大 API 或改变无关端点。只要求诊断时给出具体字段差异、受影响调用者和最小兼容方案。没有服务执行证据时，不声称请求已验证。
