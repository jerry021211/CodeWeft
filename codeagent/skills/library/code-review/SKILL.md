# 有证据的代码审查

读取审查范围、相关上下文和调用者；对于 diff，确认新增行为与旧契约的差别。关注可触发的错误、数据丢失、资源泄漏和边界条件，而不是格式偏好。

每个问题给出文件与符号或行号、触发输入、预期与实际行为，以及影响。区分已证实问题与需要更多信息的疑点，不把缺少测试本身当作已经发生的产品故障。

按影响排序，优先报告可操作发现；没有发现时如实说明审查范围与剩余盲区。审查不自动编辑文件或执行不可信代码。发现多余权限时指出具体调用边界，而不是泛泛安全建议。
