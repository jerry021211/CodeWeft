# 故障修复

读取故障相关实现与已有测试，确定实际行为、预期行为和最小失败输入。可运行检查时先记录修复前的失败；如果环境或用户限制无法执行，说明缺少的证据，不声称已复现。

沿失败路径定位根因，以最小改动恢复约定行为，保留无关修改。对边界输入先确认现有约定，不自行引入新的返回类型或错误策略。只读或仅诊断请求到根因和建议为止。

加入能在旧实现上失败的回归检查，并保留至少一个正常路径。运行最小相关测试，再按影响范围扩展。若宿主提供专门的测试工具，使用该工具并检查退出状态；没有运行工具时，明确说明未运行。

交付触发条件、根因、改动和实际验证结果。测试失败不能写成修复完成。
