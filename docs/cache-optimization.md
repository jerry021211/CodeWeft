# 缓存、工具页面与上下文整理

工具正文只受对应工具的固定上限和本次工具批次额度约束。模型窗口占用率不再把新结果改成几行预览。完整规则、实施位置和续读示例见 [工具输出策略](tool-output-policy.md)。

## 请求预算

沿用模型窗口发现和配置来源。设窗口为 W、本次实际 max_tokens 为 O、原路径的安全余量为 S，可用输入 I = W - O - S。主请求现有安全余量为 0，未新增固定余量。

- 输入估算达到 I 的 85%：记录预警，保留工具正文。
- 达到 90%：进入合法历史整理，争取降到 floor(0.70 × I)。
- 整理后仍超过 I：禁止发送，保留已完成工具结果和检查点。
- 低于硬限但未达到 70%：允许发送，记录目标未达。
- 窗口未知：沿用未知窗口行为，不猜测窗口，也不恢复 600,000 字符兜底。

缓存模式使用相同口径。旧 80% 软门槛及增长带不再决定整理触发。主请求的 300,000/480,000/600,000 字符触发和阻断不生效；300,000 字符现在仅表示一次 assistant 响应对应的工具结果批次软额度。摘要等旁路保留通用预算校验。

请求前最多尝试整理 3 次，共享 180 秒截止时间；供应商拒绝超窗后最多反应式重试 1 次；失败冷却仍为 90 秒。工具执行不因整理或恢复而重跑。

## 输出归档与缓存稳定性

生成的工具输出先写会话私有归档，再生成模型页面。每次执行保存最多 32 MiB UTF-8 正文；重试执行使用新执行标识。页面缩小和 UI 折叠不覆盖原归档，也不改写退出码。

has_more 表示还有已保存内容可读；source_complete 表示源内容是否完整保存；scan_complete 表示扫描是否完成，三者分别保存。达到归档额度后继续排空管道，档案尾部读完也不能称原始输出完整。

已生成页面原样进入历史，执行状态、范围、游标、文件版本、归档 ID 另存于检查点。执行期的文件句柄和渲染闭包不会保留在会话历史里。请求指纹只能说明请求是否稳定，不保证服务端缓存存在或命中。

## 重复读取

read_file 短引用要求规范化路径、文件版本、实际行及行内范围一致，且覆盖该范围的正文锚点仍在当前发送的消息中。不同页面不视为同一次完整读取。锚点消失或版本变化时重新交付页面。

force_full 只绕过去重，仍遵守 120,000 字符、5,000 行、批次额度、权限和版本校验。没有发现按“同类工具连续 4 次”裁剪正文的分支，因此保留原有确定性失败、重复副作用等 loop guard。

旧结果没有可恢复来源时交给摘要流程处理，不删除正文后留下失效引用。当前工具调用及结果保持配对，最新用户要求和当前批次证据保留。

## 兼容旧配置

旧工具输出、预览、摘要长度和触发比例配置键可被接受，并在覆盖固定值时给一次弃用提示，但不会改变新额度。不自动改写用户配置文件，也没有新增额度环境变量、CLI 或设置页。模型窗口、权限、执行超时和协议限制仍沿用原配置。
