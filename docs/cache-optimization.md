# 缓存友好的工具输出和压缩

本轮在现有 Agent、原始历史、请求视图、权限和 checkpoint 上增量修改。客户端请求指纹只能解释请求是否稳定，不等同于服务端缓存键，也不保证恢复后的服务端缓存仍存在。

## 配置和默认值

| 配置 | 默认 | 用途 |
| --- | ---: | --- |
| `CONTEXT_COMMAND_OUTPUT_MAX_CHARS` | 12000 | `bash` 输出超过阈值时先完整归档，再发送预览；0 关闭该额外阈值 |
| `CONTEXT_READ_REFERENCE_ENABLED` | true | 在有效请求视图中引用相同文件、相同范围的已保留原文；false 关闭 |
| `CONTEXT_SINGLE_TOOL_OUTPUT_MAX_CHARS` | 80000 | 原有单项硬预算，文件读取和其他工具沿用 |
| `CONTEXT_SUMMARY_MAX_TOKENS` | 8192 | 独立摘要输出预算，首轮和超长修复轮都预留 |
| `CONTEXT_SUMMARY_MAX_CHARS` | 4000 | 完整摘要的最终字符限制，与输出 token 上限独立 |
| `CONTEXT_CACHE_SOFT_RATIO` | 0.8 | 扣除输出预留后，模型输入窗口的软压力比例 |
| `CONTEXT_CACHE_BOUNDARY_GROWTH_RATIO` | 0.1 | Token 清理边界增长带，同时用于压缩后的空间目标 |

12000 字符是命令日志开始外置的工程默认值，与私有归档工具的一页原文预算一致，不是经真实模型证明的最优值。命令归档后的首尾预览默认共用已有的 2000 字符预算，另加路径及读取说明。文件读取不会因为这个命令专用阈值提前外置；其他工具沿用原有单项和批次预算。原始输出完整保存，原有 `is_error` 和执行状态不受影响。归档失败沿用有明确失败标记的有界截断；不能误称完整内容已保存。

8192 token 是与摘要字符目标分离的初始安全预算，不保证每种语言或推理配置都足够。提供方可能将推理计入输出额度。应按实际模型调整；`max_tokens` 等未完成响应不会提交半份摘要。SDK 前的输入预算包含该输出预留，不能把字符数当成真实 token 数或提供方的请求体字节限制。

## 归档搜索

现有 `load_tool_output` 增加可选参数，无需新增或动态切换工具：

```json
{
  "file_path": "实际归档路径",
  "query": "FAILED test_checkout",
  "max_matches": 10,
  "scan_limit_chars": 1000000
}
```

- `query` 为区分大小写的单行字面量，最多 256 字符，不执行正则。
- 返回原始 `line`（从 1 开始）和 `char_offset`（从 0 开始）的 Unicode 位置。
- `search_complete=false` 表示本次范围未扫完，按 `next_offset`、`next_char_offset` 继续；不能把当前零匹配当成全文件无匹配。
- 搜索按块读取超长行，保留跨块匹配；扫描量和结果量均有上限。扫描预算针对起始游标之后的本次搜索，定位游标仍需顺序跳过前文。
- 省略 `query` 即回到原来的范围读取，模型始终可以取得原文。
- 沿用私有根目录、路径穿越、符号链接和 junction 检查；子 Agent 使用其自己的归档根目录。

## 压缩和恢复

自动压缩只由已知模型 Token 窗口触发。普通策略在估计输入加输出预留达到窗口的 `CONTEXT_NEAR_CONTEXT_RATIO`（默认 0.8）时触发；缓存友好策略在估计输入达到扣除输出预留后窗口的 `CONTEXT_CACHE_SOFT_RATIO`（默认 0.8）时触发。窗口未知时不使用字符数兜底。旧 `CONTEXT_COMPACT_THRESHOLD_CHARS` 仍接受配置，但不参与触发。

只有已选中缓存友好策略、已知模型窗口并达到软阈值时才考虑空间目标。工具清理若已解除压力，就不会为达标额外调用摘要。需要摘要时，目标是软阈值减去一个现有增长带（默认 0.8 - 0.1 = 0.7），最低保留软阈值的一半以兼容特殊配置。目标及再次清理的增长条件仅应用于扣除输出预留后的模型输入空间，不再使用字符目标或字符增长条件。

`CONTEXT_MAX_REQUEST_CHARS` 已停用，旧环境变量及 SDK 字段不再限制完整请求容量。请求仅按已知模型 Token 窗口检查；窗口未知时不设置字符数兜底上限。单条工具输出归档、摘要最终字符验收、手动压缩与提供方超窗恢复继续沿用。

这不是新的触发阈值，也不是已证明最省钱的比例。每个边界仍最多执行三次压缩，仍受合法工具配对切点、近期保留、摘要输入预算和实际节省检查约束；无法达到目标时不强删受保护内容。事件记录目标、实际摘要次数和是否达到目标，最终硬上限独立检查。

自动软压缩保留失败冷却。手动压缩可以立即再试；硬超窗或提供方超窗恢复在冷却内最多获得一次应急机会。`summary_recovery_attempted` 进入现有 checkpoint，恢复不能反复刷新该机会。恢复失败后仍阻止超限主请求，不静默丢弃历史。旧 checkpoint 缺少该字段时使用默认值；原有 system 和请求视图快照继续沿用。工具 schema 增加参数会通过已有工具指纹触发一次受控提示词刷新。

## 验证与费用边界

离线测试覆盖真实 SDK 参数捕获、工具顺序/前缀稳定、私有搜索与跨块游标、输入预留、失败恢复次数、原始历史和配对、checkpoint 和清理边界。它们证明请求行为，不证明真实任务质量或服务端命中率。

真实对照应固定模型、推理设置、任务与工具输出，分别测首次请求和已建立前缀后的运行，纳入所有摘要、记忆、重试和失败费用。命中率使用全部缓存命中输入之和除以全部输入之和。长任务建议覆盖跨文件修复、长日志定位、多轮测试修复；报告完成质量、全部调用费用、读回次数、历史改写及耗时。

## 重复文件读取短引用

`read_file` 每次仍执行权限检查并实际读取文件。读取前后核对文件身份、大小、时间戳，并计算完整文件字节的 SHA-256；不会仅凭 mtime 或“之前读过”省略结果。文件身份或内容变化（包括请求范围之外的变化）、范围变化、读取竞态或错误都会使该次读取不能复用旧证据。

原始历史保留完整读取结果。`ContextManager.project_messages` 在摘要、工具清理和稳定请求视图之后，检查当前请求中是否存在更早的同文件同范围原文：调用参数和正文必须与该会话的读取凭据精确匹配。只有这时才把后续重复正文替换为指向原 `tool_use_id` 的短引用。短引用不作为其他引用的来源；只有字符和 UTF-8 字节都至少减少 256 才替换，小结果保持原样。磁盘上有归档、摘要提到文件、历史曾出现全文，都不等于原文仍在有效上下文里。

```json
{"file_path": "src/module.py", "offset": 20, "limit": 80, "force_full": true}
```

`force_full=true` 禁用本次读取的短引用，适用于用户或模型要求重新展开原文；它不绕过已有输出和上下文预算。全局关闭使用 `CONTEXT_READ_REFERENCE_ENABLED=false`，策略切换记录 `read_reference_policy_changed`。工具 schema 的新增参数会通过原有指纹触发一次受控刷新。短引用沿用现有投影占位符保护，不能作为写入或替换的文件正文。

压缩或清理移除引用来源后，投影从保留的原始读取结果重新展开必要正文，再让后续重复读取引用它；不会留下指向摘要或已清理正文的引用。正常追加新消息不改变旧请求前缀。文件后来改变不会重写之前的历史快照，但下一次实际读取必须重新验证，内容变化时返回新正文。

读取凭据存放在会话自己的 `RuntimeState.read_references`，随现有 checkpoint 持久化，只包含路径、范围、版本和指纹，不额外保存正文。恢复时重新检查有效请求内容；新读取还会重新检查磁盘文件。旧 checkpoint 缺失凭据、版本不支持或内容不匹配时，保守返回原文，不从旧计数推断“读过”。共享只读工具实例的并发 Agent 也不共享这些凭据。摘要输入仍取原始历史，不含这份实现状态。

只有内置读取工具产生的有效凭据参与优化；自定义工具或执行包装器若把结果转成普通字符串、丢失凭据，则保守禁用引用。归档预览、被 hook 改写的正文、失败结果、歧义调用 ID 都不能充当原文来源。

`context.request_projected` 记录当前请求的 `read_reference_count` 和 `read_reference_chars_saved`，不记录新正文，也不把字符节省冒充真实 token/费用节省。此项优化减少模型新增输入，不省略磁盘读取，未以真实付费 API 验证任务质量和费用收益。
