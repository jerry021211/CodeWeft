# 开发热更新

前端复用现有 Vite + React 热更新；后端通过显式 `--reload` 开关使用 Uvicorn 的文件监听和子进程重启。默认启动行为保持不变，不进行 Python 模块原地替换。

## 启动

从仓库根目录运行，使用已安装 `.[web]` 的 Python 环境：

```powershell
# 终端一：后端代码自动重载
python -m codeagent.web.cli --workspace . --port 8765 --reload

# 终端二：前端热更新
npm.cmd --prefix web run dev
```

打开 `http://127.0.0.1:5173`。首次开发先执行 `python -m pip install -e ".[web]"` 和 `npm.cmd --prefix web ci`。macOS / Linux 将 `npm.cmd` 替换为 `npm`。

已安装的 `codeagent-web` 命令也支持 `--reload`。`--workspace` 可以指定另一个项目的路径；每次重载仍使用该项目，不会切回启动目录。前端的默认代理端口为 8765。

## 生效范围

| 修改内容 | 如何生效 |
| --- | --- |
| `web/src/` 的 React、TypeScript、CSS | Vite 热更新；无法局部替换时自动刷新页面 |
| CodeWeft `codeagent/` 下的 Python 源码 | 启用 `--reload` 后自动重启后端 |
| 业务项目文件、日志、数据库、`web/dist/`、仓库外文件 | 不因这些文件变化触发后端重启 |
| `.env`、依赖、非 Python 模板文件 | 不在本次自动监听范围；手动重启相应开发服务，依赖变化需先安装 |
| 设置页面中的模型配置、MCP | 沿用现有在线更新机制及其运行状态限制 |

监听目录由当前安装的 CodeWeft 源码位置确定，而不是业务工作区。开发请使用可编辑安装 `pip install -e ".[web]"`。如果让 Agent 修改 CodeWeft 自身的 Python 文件，也会触发重载；执行这类任务时应关闭 `--reload`。

访问后端的 `8765` 端口仍然看到 `web/dist/` 构建版本；前端热更新需要访问 Vite 的 `5173` 端口。生产构建继续使用 `npm.cmd --prefix web run build`。

## 任务与重启边界

后端热更新属于开发自动重启，**不会让运行中任务无中断地切换到新代码**。检测到源码变动后，Uvicorn 结束旧服务，再由新的子进程重新创建应用、数据库连接和调度器，监听父进程不创建这些运行时资源。

开发重载最多等待已有 HTTP/SSE 连接 5 秒，然后进入现有应用关闭流程：停止定时调度、停止团队监督、取消并等待普通执行线程清理资源。5 秒仅是连接等待上限，不是强制杀死 Agent 线程的期限；工具或模型调用若迟迟不退出，后端重启也可能等待。

会话、计划和已落盘事件保留在原运行时数据目录；未完成任务继续遵循现有取消、中断和恢复语义，不自动重放结果不明的工具调用。定时任务也沿用现有离线补触发和防重放规则。语法错误会使新子进程启动失败，修正并保存后会再次尝试加载。

重启期间页面可能短暂显示请求失败，SSE 会重新连接。本地会话 Cookie 会随服务进程轮换；旧 Cookie 的请求可能先返回一次 403 并更新 Cookie，再次请求或刷新页面即可恢复。已有修改请求不会被自动重复提交。

正常长期运行时去掉 `--reload`，继续使用原来的启动方式。
