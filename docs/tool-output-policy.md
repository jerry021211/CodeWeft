# 工具输出超限策略与改造记录

对应用户提供的 01–19 方案。固定值集中在 `codeagent/tools/output_limits.py`。字符使用 Python `len(str)`；归档字节使用实际保存的 UTF-8 编码长度；请求 tokens 使用原估算器。三种单位不互相替代。

## 固定额度

| 内容 | 正文上限 | 数量或其他上限 |
| --- | ---: | --- |
| read_file | 120,000 字符/次（批量共享） | 每个文件最多5,000行；file_paths最多5个文件 |
| repo_map | 32,000 字符/次 | 默认深度4、200文件；标签按文件名/路径推断 |
| grep | 32,000 字符/页 | 1,000 条匹配行记录 |
| glob | 32,000 字符/页 | 1,000 条完整路径 |
| search_code | 48,000 字符/次 | top_k 默认及最大 20 |
| bash / 经 bash 运行的测试 | 60,000 字符/次 | stdout/stderr 共享归档额度 |
| 网页快照 | 120,000 字符/页 | 使用既有已识别 MCP 网页工具 |
| web_search | 48,000 字符/次 | max_results 默认及最大 10 |
| 未分类工具 | 120,000 字符/次 | 按工具身份确定一种策略 |
| load_tool_output | 120,000 字符/页 | 5,000 行 |
| load_context_history | 合计 120,000 字符/页 | 10 消息、每条正文 24,000 字符 |
| 归档字面量搜索 | 120,000 字符/页 | 20 匹配、扫描 4,000,000 字符、查询 1–256 字符 |
| load_skill | 120,000 字符，合格时完整交付 | 文件最多 524,288 字节 |
| 每次生成输出归档 | 不按字符计量 | 33,554,432 UTF-8 字节 |
| 每条结果元数据 | 2,000 字符 | 与正文分开计数 |
| 同次 assistant 响应的工具批次 | 合计 300,000 字符软额度 | 正文、元数据、反馈均计入 |

正文中的行号、分隔符和省略说明计入正文额度。范围参数可选择较小页面，不能提高固定上限；布尔值不能冒充整数。

## 按 01–19 的修改位置

1. **常量与结果元数据**：新增 `tools/output_limits.py`、`tools/output_pages.py`，扩展 `ToolOutput`。保留 status、exit_code、outcome、process_id、file_read_snapshot，增加实际范围、恢复游标、has_more、source_complete、scan_complete、output_id、truncated_reason、storage_error。元数据在合法 tool_result 文本中渲染，内部记录不作为供应商协议额外字段发送。
2. **原始归档**：新增 `context/output_archive.py`。UUID 标识一次输出，正文和 manifest 分别持久化；按 UTF-8 字节限制，保留字符边界、通道和采集顺序。缩页不覆盖原档案。写入失败保留有界证据及真实状态，返回 storage_error，不承诺失败引用可回读。
3. **read_file**：`tools/read.py` 流式连续分页，默认及最大 limit=5,000；普通行尽量完整，超长行按行内位置续读。校验 stat、文件身份和分块 hash；读取期间变化则丢弃整页。批次缩页复用同一分页器；不提前统计总行数，不归档复制大源文件。
4. **grep**：`tools/grep.py`、`tools/search_files.py` 按稳定路径及源行顺序返回整条记录，单位为一个匹配源行。长行保留命中附近连续片段、字符范围和 read_file 定位参数。游标按实际交付数量推进，权限跳过和提前停止标为扫描未完成。
5. **glob**：`tools/glob_tool.py` 与共用分页器稳定排序、完整路径交付，不截路径、不生成假 EOF 游标。空页无法容纳的超大记录有明确错误，可通过输出归档定位。
6. **代码检索**：`code_search/service.py` 与 `tools/search_code.py` 统一 top_k 1–20，替换原 7,900 字符逻辑。48,000 字符页面按合法 JSON 对象构造，优先排名靠前证据；缩段保留连续代码及实际行范围，保留索引代次和可信度字段。
7. **bash**：`tools/bash.py` 改为 stdout/stderr 并行排空、增量解码、分块归档，不再全读无限临时文件。达到归档额度继续排空。60,000 字符内完整交付；超限按带位置的头尾片段预览，错误时优先可识别错误、断言及堆栈。
8. **测试日志**：复用 bash，不增加 run_tests 工具。保留框架明确报告的统计及真实退出码，片段按原顺序展示并去重叠；缺失统计不补造。查看更多日志不重跑测试。
9. **网页与搜索**：`tools/web_search.py` 将 max_results 统一到 1–10，完整条目保留 URL，先缩摘要再减少末尾结果。已识别网页 MCP 使用同次响应的归档快照分页，附 URL 或 manifest 映射，避免重新抓取后拼接版本；原网络和 HTTP 限制不变。
10. **MCP/兜底**：`mcp/router.py` 根据明确工具身份选择策略，保留错误状态。JSON 在完整字段或记录层处理；数组在结构化结果中仍是数组，不切坏序列化文本。当前桥接通道只支持文本：图片、音频等明确标为不支持，保留类型及可用资源引用，不把 Base64 展开为正文、不声称模型已看到媒体。
11. **归档与历史回读**：`tools/runtime_data.py` 使用流式页和真实游标。历史单条消息未读完立即停页，下页先接消息尾部。归档搜索保持大小写敏感字面量匹配，保留分块重叠、未交付匹配和续扫位置。档案读完与源输出完整分别报告。
12. **批次预算**：`ContextManager.finalize_tool_results` 每次 assistant 响应独立处理，有自己的批次标识。先预留元数据和成功 load_skill 全文，再按错误/阻断、显式读取、其他结果分配；同类均分，余数按调用顺序。游标导致元数据长度变化时重新分配，调用原分页器，不统一切字符串。零正文仍保留状态和起点恢复入口。
13. **上下文压力**：当前工具页不再经过按窗口压力裁剪的投影。合法历史整理后重算完整请求；仍超硬限则停发，保留完成结果。没有可恢复原文的旧结果进入摘要流程。
14. **内存与持久化**：`agent.py` 在执行、反馈、批次处理间保留带属性结果；最终历史保存有界页面，检查点独立保存执行事实和恢复信息。不按 120,000 字符截整个存储 JSON；历史不持有归档句柄或捕获完整原始响应的渲染闭包。
15. **重复读取与循环检测**：`context/read_references.py` 保留实际范围及版本证据，只有当前请求中存在覆盖正文锚点才短引用。未发现“同类连续 4 次”裁剪分支，因此没有误删既有失败或副作用检测。force_full 不绕过固定额度和校验。
16. **技能全文**：`skills/loader.py`、`tools/skill.py` 有界读取，校验 512 KiB 文件和 120,000 字符正文，读取中增长也会检测。超额明确报错和提示拆分，合格全文不摘要或驱逐。请求通过硬校验后才登记已交付技能，失败不覆盖此前成功记录。
17. **请求预算**：主路径按 `I=W-O-S`，85% 预警、90% 整理、70% 目标、超过 I 禁止发送。保留现有窗口来源和安全余量，没有重新启用 300,000/480,000/600,000 主请求字符门槛。请求前最多 3 次整理、供应商超窗最多 1 次恢复、90 秒失败冷却。
18. **摘要**：新增 `context/summary_chunks.py`。选定完整合法历史前缀后分块，大字段连续切片并保留字段和位置。最多 16 个原始块，每块 32,000 估算 tokens；每次摘要调用固定预留 32,768 输出 tokens，并检查摘要模型自己的窗口。多块有序合并，累计旧摘要参与；最终最多 16,000 字符，超长最多重写一次。整个整理流程共享 180 秒截止时间。提交须材料覆盖、工具配对合法、引用有效、历史未变化、至少节省 max(256 字符, 5%) 且 token 估算下降；失败保留原文和旧摘要。
19. **废弃配置与重复截断**：`config.py`、`context/models.py` 停用旧工具/预览/摘要额度覆盖，接受兼容键但忽略值并提示弃用。移除运行链中的 15,000→头6,000尾3,000、12,000→约2,000、旧 200,000 批次、7,900 检索、50,000 字节技能等旧路径。同步 README、缓存文档和回归预期，未自动修改用户配置文件。

## 续读示例

读取源码首页：

```json
{"file_path":"src/example.py","offset":1,"limit":5000}
```

后续使用该页返回的 `next_cursor`。其中 `expected_version` 必须使用上一页实际 `source_version`。`char_offset` 是起始源行内解码字符位置，不包含显示行号。

批量读取用 `{"file_paths":["src/main.py","tests/test_main.py"]}`，不能同时传 `file_path`。
批量正文共享120,000字符预算；每个文件分别保留元数据，缩页复用源码分页器，不截断版本/游标。
单文件失败仍返回其他文件。每个文件按自己的 `next_cursor` 使用单文件接口续读，不共用版本。
批量结果当前保留原文，不参与单文件重复读取短引用；单文件的原有引用机制保持有效。

项目概览使用 `repo_map({"depth":2})`，然后用 `repo_map({"path":"src"})` 下钻。
工具只列文件路径、大小和按命名推断的标签，不读取源码或调用embedding。
默认深度4、最多200文件，沿用glob的Git忽略规则和非Git目录排除规则；输出省略会明确提示。

读取命令归档：

```json
{"output_id":"返回的32位归档ID","offset":1,"limit":5000,"char_offset":0}
```

查找已保存的失败日志：

```json
{"output_id":"返回的32位归档ID","query":"AssertionError","max_matches":20,"max_scan_chars":4000000}
```

`scan_complete=false` 时按 `next_cursor` 续扫。页面容不下第一个匹配会明确报告并停在该匹配；可增加本次 `char_limit`（最多 120,000），或直接按返回位置读取原文。原归档不完整时，扫描完也只证明已保存范围内的结果。

## 验证范围

回归覆盖真实 stdout/stderr 子进程及退出码、UTF-8 归档额度、归档写失败、取消状态、read_file 长行/版本/EOF、批次公平分配与零正文、JSON 合法性、跨块字面量搜索、历史续读、技能超额、摘要材料覆盖及历史版本保护、45 轮任务检查点恢复。具体运行数量以交付说明和测试日志为准。

结构检查证明材料按指定范围提交、引用和配对满足约束，不能证明模型摘要语义绝对没有遗漏。Token 数量仍是原估算器的估计值；供应商实际超窗保留有界恢复。第三方 MCP 真实服务及供应商在线行为需在对应部署环境验证。
