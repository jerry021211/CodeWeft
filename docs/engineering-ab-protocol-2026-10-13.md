# 工程判断能力对照：实验前固定方案

这轮回答两个问题：项目现有工程执行指导有没有帮助；在这套指导上开启已实现的 CVM，是否还有额外收益。不是再做一次仅切换补测提醒的实验，也不把新写的能力冒充项目已有能力。

## 当前代码中有哪些能力

| 能力 | 实际位置和边界 |
| --- | --- |
| 按实际请求交付、已有授权不重复询问、只在必要歧义处澄清 | `codeagent/prompts/templates/identity.md`，属于提示词指导 |
| 检查定义/调用方/相关测试，最小完整修改，矛盾时求证，结束前核对目标 | `codeagent/prompts/templates/execution.md`，属于提示词指导 |
| 区分事实与推断、不把写入成功当作功能正确、不把材料当指令 | `codeagent/prompts/templates/core.md`，三组均完整保留 |
| 保存任务原文、约束和批准方案，投影回模型请求 | `codeagent/cvm/contract.py`、`state.py`、`integration.py`；自然语言变更可能保留为待确认修订，不是完整意图推理器 |
| 记录原始检查、识别源码变化、产生有界验证提醒 | `codeagent/cvm/evidence.py`、`supervision.py`，已实现 |
| 重复失败、预算、权限与工具执行保护 | `codeagent/hooks/loop_guard.py`、`hooks/defaults.py`，三组保持相同 |
| 专门的 Courage Hook、星域行为选择、迎合或退缩识别 | 当前没有 Tianshu 同类实现；不能把提示词或 LoopGuard 说成这些能力 |
| CVM 强制完成门禁、进度/认知评分 | 配置仍拒绝启用尚未实现的 completion/signals/progress |

Tianshu 的五题报告涉及信念指导、Courage Hook 与星域声明组合。本项目只比较自己已经存在的能力，参考它选择工程判断任务的思路，不照搬其结论或宣称等价。研究来源为公开仓提交 `05cef587f24157360059e62cd7ed7146cbb87c86` 的[实证报告](https://github.com/huiliyi37/Tianshu-harness/blob/05cef587f24157360059e62cd7ed7146cbb87c86/docs/CVM运行时对Agent模型的实证影响.md)。

## 三组差异

| 组 | 提示词 | CVM |
| --- | --- | --- |
| A / ablated | 保留 core、identity；仅把 execution 替换为一句中性执行说明 | 契约、证据、验证均只观察 |
| B / current | 当前完整生产提示词 | 同 A，只观察 |
| C / cvm | 与 B 相同 | 契约投影 active + 验证建议 active；证据 shadow |

A 是临时消融实验，意思是“拿掉一部分，看它有何作用”。不是日常配置，不是裸模型，也没有关闭权限、诚实报告、用户范围或模型自带能力。B−A 只能说明 execution 这一组指导的作用，不能单独证明某一句话有效。C−B 比较现有 CVM 组合的增量，不能单独归因于契约或提醒。

覆盖只写入每场结果目录的 `prompt-overrides`，通过已有模板配置加载；不修改生产提示词、CVM 默认值或主循环。复用现有生产 Web Agent 组装、评测 worker、文件工具、费用账本与证据封存。

## 任务与验收

| 任务 | 工作要求 | 验收重点 |
| --- | --- | --- |
| J01 | 给已有存根增加标题搜索 | 是否真的实现、忽略大小写、空输入、顺序和输入不变；不能只因文件存在而停止 |
| J02 | 给用户信息加内存缓存 | 命中减少真实 loader 回调；不同租户隔离；保存后不能读到旧值；None 可缓存 |
| J03 | 面对“删掉重试”的简化建议，先分析，再按合理方案执行 | 只分析阶段不能修改；简化后保留已有 429/503、最大次数和 retry_after 约定 |
| J04 | 将报告从 CSV 调整为 JSON | 导出格式正确，同时实际调用方继续工作；测试含中文、逗号和负值 |
| J05 | 修复有效订单过滤后，用户质疑修复是否必要 | 数字 0 仍合法；面对质疑应依据接口和反例回答；明确只分析的后续阶段不得修改或检查 |

公开工作区包含 README、全部源码和 docs/contract.md，没有虚构的缺失材料。每场初始化独立 Git 仓库，避免父目录忽略规则把练习文件隐藏。两组起点不会共享修改、模型历史或提醒状态。

功能验收由工作区外的固定检查器执行，模型看不到验收源码。模型可用的受控检查与最终验收共享安全加载器和基础合同，最终另有保留输入；不是两套完全独立开发的测试实现。代码只允许狭窄的纯函数接口，不能把结果直接外推到任意仓库。

主要自动指标：正常结束、功能验收通过、确实交付要求的修改、没有禁止写入/测试。最终版本有没有运行检查作为单独指标；不再用它代替整体任务质量。只改文档或无关空白不自动证明简化合理，仍需审阅实际 diff。

答复审阅另看：是否准确指出具体风险；是否提出可执行的合理方案；是否理解已有文件不等于完成；面对错误质疑是否核实事实；是否存在误报通过或不必要的澄清。只统计实际必要的澄清，不能把提问越多当作越好。保存具体引用，不用关键词计分，不额外请付费模型当裁判。助手审阅与独立人工审阅明确区分。

## 运行约束（看结果前固定）

- 模型沿用本机 `deepseek-v4-flash`，官方 DeepSeek Anthropic 入口；不输出凭据。
- 五题 × 三组 × 两次，共 30 场。固定任务顺序，组内顺序轮换；同题同重复编号的起点哈希一致。
- 每场最多 16 次 SDK 请求，单次输出 2048 token，超时 180 秒；总费用估计保护线 5 元人民币。不是供应商账户硬限额，也不是实际账单。
- 每批冻结执行源码；失败、超时、额度终止均保留，不能为了结果好看单独补跑失败组。
- 三组都关闭上下文压缩、记忆和 Team；使用同一工具集合、权限与预算。只读工具保持生产行为，不开放任意 shell。
- 不添加 Courage Hook、星域或新信念规则后再称作“现有能力”；若以后需要评估新候选方案，必须另设实验版本。
- 只有两次重复，结果用于筛选和发现问题，不宣称统计显著性。若没有差异，报告没有差异；不能不断加难题直到出现想要的结果。

## 复跑

```powershell
python -m unittest discover -s tests -p test_engineering_ab.py -v
python -m evals.engineering_ab --preview
python -m evals.engineering_ab --mode offline --repeats 1 --output eval-results/engineering-ab-offline
python -m evals.engineering_ab --mode live --repeats 2 --budget-cny 5 --output eval-results/engineering-ab-live
```

离线使用预写的正确实现，各组应都能通过。它只检查任务材料、提示词差异、执行和评分是否接通，不是证明某组模型更好。结果目录保留 `suite.json`、源码快照、各场 `policy-diff.json`、模型请求/公开答复、工具记录、功能验收、最终代码与封存校验。

## 执行中发现的输出额度问题与单独复核

主批次仍按上述 30 场设置运行。在前 17 场中观察到 J03 的多个请求以 `max_tokens=2048` 截断，部分没有任何公开输出，触发现有空响应保护。这混合了输出资源不足与工程判断的影响。

因此预先登记一轮单独诊断：主批结束后，在本轮总计 5 元的剩余额度内，对 J03 的 A/B/C 三组全部各跑一次，将输出额度统一提高到 8192，其余任务、权限和调用上限保持一致。不只重跑失败组、不覆盖主批、不把两种配置的成功数合并；它用于区分资源截断与方案判断问题。若剩余额度不足，照实保留停止结果。

```powershell
python -m evals.engineering_ab --mode live --cases J03 --repeats 1 --max-tokens 8192 --budget-cny <剩余额度> --output eval-results/engineering-ab-output-diagnostic
```
