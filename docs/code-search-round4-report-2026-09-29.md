# 第四轮：首次引用协议与任务收尾验证（2026-09-29）

本轮保留程序生成引用、B2 通用改写门控。最终产品仅改 `codeagent/agent.py` 和 `codeagent/source_citations.py`，另补两项机制测试及使用文档。没有修改 RRF、候选数、搜索实现、调用额度或冻结评分器。首次遵循有所改善，但尚未消除格式修复；不能把引用可靠性的变化说成召回或排序能力提升。

## 最小实现与失败方案

保留原系统协议，在首次工具执行后已有可信来源时，将一次运行时协议提醒附到工具结果消息末尾。模型仍自行选择来源和行段，程序仍从同一份源码生成展示字段。提醒本身不触发额外模型请求；发生不合规时仍最多纠正一次，使用原预算。直接普通回答不增加提醒。

新发现的漏洞是“旧路径/正文对象再附上 source_ref”。程序原本会明确拒绝这种混合对象，但纠正入口只识别没有 source_ref 的旧对象。现在混合字段及缺少坐标也进入同一次格式纠正，程序不会自行删除字段、模糊匹配或迁移引用。来源不明、过期或行段无效依然明确报错。

按时间保留三个候选：①仅强化系统说明（candidate-engine，focus-b4），首次 2/8；②一次运行时提醒（final-engine，focus-final），首次 3/8，但暴露混合字段；③明确三字段限制并补纠正入口（final-engine-v2，最终保留）。前两版不是最终版本的重复试验，失败记录全部保留。最终恢复了 B3 原系统说明，避免堆积没有证实有效的长提示。

## 指标与分母

- **首次格式遵循**：只看主 Agent 第一次 end_turn，排除 search_code 查询改写的旁路请求。引用对象必须只有 source_ref/start_line/end_line，类型与区间有效；这只是格式指标，来源真实性另算。分母是首次回答中实际提交引用的任务，未交答案单列；完整回归另列全部 16 道正例分母，防止幸存者偏差。
- **冻结 Hit@1 / Hit@5**：最终答案前一条/前五条是否满足冻结的路径、精确符号、源码片段、行为锚点和该题 20 行约束。完整集分母为 16 道正例，失败也计入；四道不存在题独立统计。这不是工具候选排名。
- **函数定位诊断**：仅核对最终输出的路径和符号，忽略引用一致性；不替代冻结评分，也不从已读到的工具结果补分。
- **引用一致性**：逐条检查最终前五个返回对象的正文、行段、限定名及版本。未解析对象计不一致；没有答案的题通过任务完成率体现，不能把“已返回引用 100%”说成全部任务正确。
- **跨文件找全**：四道跨文件题覆盖全部冻结环节；针对性集含 C01 两次，分母为 2。
