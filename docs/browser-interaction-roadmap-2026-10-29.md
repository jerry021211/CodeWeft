# 浏览器交互后续计划

日期：2026-10-29。更新：2026-10-30。状态：审批模式与第二期已实现并通过自动验收，第三期继续保留为后续计划。

## 已完成的第一期

已提交版本 `4eaddad`：通过 Playwright MCP 操作独立 Chrome/Edge 窗口，支持可见与后台预设。使用临时浏览器环境，同一项目同名服务由一次 Agent 执行独占，执行结束关闭连接；后续调用重新启动。配置持久保存，不要求每次重新配置。

第一期功能和验证入口见 [使用指南](usage-guide.md#浏览器操作第一期)。第二期增加下述会话管理，仍没有侧栏网页画面，MCP 图片也尚未作为视觉输入传给模型。

## 第二期：会话连续性、状态展示和人工接管

目标：用户能看到 Agent 正在操作哪个页面，临时接管独立浏览器窗口，完成登录或人工输入后交还 Agent。

按以下顺序实现，不一次引入完整浏览器工作台：

1. 明确浏览器会话归属，以会话管理页面和临时资料；同一浏览器同一时刻只能有一个控制者。沿用第一期独占和超时清理机制，不能简单关闭任务结束清理后让多个会话共享同一页面。
2. 侧栏先展示状态、页面标题、地址和错误，提供外部打开入口；不内嵌网页。页面与登录状态仅在受控浏览器会话内跨对话轮次保留，不默认使用用户日常浏览器资料，也不承诺后端重启后恢复。
3. 增加“接管浏览器 / 交还 Agent”：进入接管前停止派发新操作，等待或确认在途操作结束；无法确认结束时不能显示接管成功。用户控制期间 Agent 不操作浏览器，交还后重新读取页面状态，不能复用旧元素引用。
4. 增加显式关闭和闲置清理；删除会话、撤销服务信任、配置变更、取消和崩溃都有明确的清理与恢复结果。

浏览器控制权与工具审批分开：用户交还控制权不等于授权发送邮件、付款或上传本地文件。复用审批模式，不再增加另一套浏览器审批规则。

验收：跨轮保留页面；两个会话不会串页或串登录；接管时无并发点击；交还后刷新快照；在途超时不误报已停止；关闭和异常不会留下可被其他会话误用的浏览器状态。

### 第二期实现范围（2026-10-30）

- Web 自动适配现有受支持的浏览器预设：固定 Playwright MCP 0.0.83、Chrome/Edge、`--isolated` 和 `lifecycle: "execution"`，允许 `--headless`。不修改配置、不撤销已有信任；其他 MCP 与 CLI 仍使用原生命周期。自定义命令路径、环境变量、工作目录或额外启动参数不适配。
- 每个会话/工作区/服务使用独立连接和临时浏览器环境。同一浏览器每次只允许一个 Agent 持有，正常轮次结束释放 Agent 控制者但保留页面。
- 右侧「浏览器」显示最近确认的标题、地址、控制状态和错误；外部打开只打开地址，不共享受控窗口的登录状态。
- 「接管」立即阻止新工具操作，在途操作完成且结果已知后才显示「由你控制」。接管期间的 Agent 调用返回未执行；若本轮结束，交还后用户发送消息继续。
- 「交还」先读取当前快照，随后要求 Agent 自己获取新快照才能执行下一步，禁止直接使用交还前的旧元素引用。后台模式不支持人工接管。
- 闲置 30 分钟、显式关闭、取消、删除会话、配置/信任变化或正常服务退出触发清理。未知结果隔离并显示错误；清理未确认保持「正在关闭」。崩溃重启后不恢复旧页面或登录状态。
- 复用了 MCP 的进程清理，修复停止信号与重复取消竞争导致退出栈中断的问题。浏览器控制不改变审批模式、只读及工作区限制。

验证入口：`tests/test_browser_sessions.py`、`web/tests/browserPanel.test.mjs`；真实 Chrome 本地页面回归见 `tests/test_browser_session_smoke.py`（设置 `CODEAGENT_BROWSER_SMOKE=1`）。不使用个人浏览器资料或真实账号。

本轮结果：后端相关回归 191 项、前端 142 项全部通过，类型检查和生产构建通过。
另用真实 Chrome 验证本地页面跨轮数据保留、不同会话隔离、关闭与重新打开后的清理；
使用隔离页面验证了侧栏接管/交还/关闭按钮和窄屏布局。构建仍有原有大包体积提示。
未进行真实账号登录或线上表单提交验收，未重启用户正在运行的服务。

## 第三期：侧栏实时预览与交互

目标：在 Web 工作台侧栏看到受控浏览器画面，并在人工接管状态下直接操作。

1. 先实现只读画面和当前页面状态，再实现鼠标、键盘输入转发；继续使用第二期的会话归属和控制权状态。
2. 实现前验证现有 MCP 后端是否暴露画面传输能力；不足时增加窄范围的浏览器画面桥接接口。传输方案做小规模验证后再选择，不预设 Electron 或其他桌面客户端。
3. 不将普通 iframe 当作任意站点的浏览器预览；也不将截图展示等同于模型已经能看图。
4. 单独处理画面更新节流、坐标映射、断线恢复和控制权校验，避免前端卡顿或旧页面操作。

验收：画面和当前页面一致；侧栏缩放后的点击位置正确；只有当前控制者能输入；断线不重放点击；不会泄露其他会话的画面或输入。
