# 定时任务

在 Web 工作台左侧打开 **设置 → 定时任务 → 新建定时任务**，填写项目绝对路径、任务名称和提示词，选择执行方式并保存。

- **指定时间执行一次**：在未来的指定时间提交一个任务，触发后自动停用。
- **固定间隔重复**：从首次执行时间开始，以 60 秒至 365 天的固定间隔重复。3600 秒为一小时，86400 秒为一天。按实际经过时间计算，不是带夏令时规则的每日日历计划；当前不支持 Cron 表达式。

输入和展示时间采用浏览器所在时区，后端统一保存为 UTC。页面显示当前时区。夏令时切换导致不存在的本地时间会被拒绝；重复出现的本地时间采用浏览器的默认解析结果，需要精确指定时可通过 API 传入带偏移量的时间。

任务默认只读，可切换为 Agent 执行。每次运行使用当前已保存的模型配置、原有工具权限和审批流程；定时触发不会自动批准工具调用。请先完成模型配置。

## 管理和结果

列表支持编辑、暂停、启用和删除。编辑会重新设置首次执行时间；恢复周期任务时，选择原始时间序列中下一个未来时间，不补跑暂停期间的任务。已经触发或过期的单次任务，需要编辑为未来时间后再次启用。

每次触发创建一个新的项目会话，提示词独立执行，不继承其他聊天的上下文。在 **执行记录 → 查看会话** 中查看输出、工具调用和审批。打开已归档的结果会话会恢复该会话。执行记录显示最近 50 次触发，API 最多返回最近 200 次。

暂停、编辑和删除只影响后续调度。已领取的触发和已提交的运行仍可继续；需要停止时，在对应会话中取消。删除计划会删除其触发记录，但保留生成的会话及项目文件；删除会话后，触发记录保留但不再提供会话入口。

## 运行与重启

保持 **CodeWeft 后端进程运行**；浏览器可关闭。它不会唤醒关闭的计算机，也不是操作系统级定时服务。计划和触发记录保存在现有运行时 SQLite 数据库，默认每秒检查一次，实际开始时间受并发队列和机器负载影响。

- 服务重启后，过期单次任务执行一次；周期任务错过的多个周期合并为一次，然后恢复原来的时间序列。
- 同一计划的上一轮仍在提交、排队、运行或原生协作执行时，本次触发标记为跳过，避免重叠；不同计划共享原有的并发上限。
- 提交失败记录错误，单次任务不会自动重试；周期任务在下一个计划时间继续尝试。
- 调度先在数据库中原子领取并推进时间，再提交运行。如果进程在中间退出，该次提交标记为中断，不自动重放；检查关联会话后自行决定是否重新安排。这是避免重复外部操作的“至多提交一次”策略，不保证每次触发都成功执行。

沿用本地单进程部署方式，使用 `python -m codeagent.web.cli --workspace . --port 8765`；不要让多个 Web 进程共享同一运行时数据库。

## HTTP API

接口沿用本地会话 Cookie 和同源请求保护。首次 GET `/api/health` 可初始化当前进程的会话 Cookie。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/schedules` | 列出计划 |
| POST | `/api/schedules` | 创建计划 |
| PUT | `/api/schedules/{id}` | 替换计划配置 |
| PATCH | `/api/schedules/{id}` | 传入 `{"enabled": false}` 暂停，或 `true` 启用 |
| DELETE | `/api/schedules/{id}` | 删除计划和触发记录 |
| GET | `/api/schedules/{id}/history?limit=50` | 查看触发、运行状态及结果会话 |

创建和替换请求示例（替换为实际项目路径和未来时间）：

```json
{
  "name": "每小时项目巡检",
  "workspace": "D:\\projects\\my-app",
  "prompt": "检查项目中的 TODO 和最近改动，给出简短报告，不修改文件。",
  "kind": "interval",
  "run_at": "2030-01-01T09:00:00+08:00",
  "interval_seconds": 3600,
  "read_only": true,
  "enabled": true
}
```

单次任务使用 `"kind": "once"`，`interval_seconds` 省略或设为 `null`。
