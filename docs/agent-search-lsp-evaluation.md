# 向量检索 + LSP：补充真实 Agent 对照

**18次新增真实执行已完成。** 本批结果没有证明LSP提高整体Agent成功率或效率。
编辑反馈确实进入了模型上下文，但有效诊断只覆盖2次编辑；定义/引用工具未被Agent主动调用。

本轮仅新增D组18次执行，与既有C组首轮18题比较。A/B/C不重跑，既有成绩、日志和索引文件保留。
证据目录：`eval-results/agent-three-arm-20261003/lsp-arm-v1`。

## 固定设计

- 同一份冻结生产引擎、源码、任务、评分标准、工作区路径和模型；仅增加生产 `lsp` 工具。
- DeepSeek Flash负责Agent；`qwen3.7-text-embedding-flash`负责向量。复制既有C组缓存到D组独立索引，不重新整库付费建库。
- 沿用18题首轮顺序，每题最多8次模型请求、24次工具、80000 token、120秒，输出上限3000 token。
- LSP按需冷启动，每题独立服务，默认单次请求5秒、编辑反馈1.5秒；不提前为模型启动服务器。
- 原有 `PostToolUse` 通过 `changed_files` 同步修改并生成诊断。实际检查后续模型请求中是否存在 `<edit_diagnostics>`，不以注册了hook代替反馈成功。
- 保存真实LSP返回、调用耗时、诊断状态、进程PID与释放结果；模型自行选择工具，不注入或强制LSP动作。
- 同时保留预注册严格交付评分和既有辅助JSON提取验收；证据仍核对原始路径、行号、逐字源码与全部关键行。

## 真实服务器预检

Python使用pylsp，TypeScript使用typescript-language-server，Java使用本机VS Code所带JDT LS。
在原测试范围的独立副本上，三者均成功完成跨文件定义跳转，预检进程全部释放；未使用模拟服务器。
预检独立于计时Agent任务，不把探测结果或位置提示交给模型。

## 比较边界

这是C历史对照+D后续执行，时间与服务端缓存没有同期随机化；变化不能完全归因于LSP。
为保持源码范围一致，没有只给D组补充完整构建文件或依赖。预检能导航，并不代表完整项目依赖环境就绪，
诊断可能包含缺少依赖等环境噪声。
这18题中的修复主要是逻辑条件回归，而非语法或类型错误，通常不在LSP诊断的优势范围。
因此本轮评价的是当前任务与当前Agent工具选择下的增量效果，不能外推为LSP普遍有用或无用。

费用沿用上一轮标准：DeepSeek Flash闲时未缓存输入1元/百万token、缓存输入0.02元、输出4元；
北京区Qwen Flash同步embedding为0.125元/百万输入token。
来源：[DeepSeek价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)、
[阿里云embedding价格](https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api)。
不重复计入已经完成的向量冷建费用；D组新增请求和维护费用单列。

| 同一首轮任务数 | 18 | 18 |
| 平均Agent时间（秒） | 10.68 | 11.72 |
| 加索引准备后的平均时间（秒） | 12.95 | 14.48 |
| 平均聊天token | 36,625 | 40,463 |
| 平均热运行费用，含任务向量/维护（元） | 0.011790 | 0.012875 |
| 平均模型请求数 | 4.83 | 5.17 |
| 严格JSON交付通过 | 6/18 | 5/18 |
| 辅助JSON提取后验收通过 | 16/18 | 17/18 |
| 修复题隐藏契约通过 | 5/6 | 5/6 |
| 编辑反馈进入模型上下文 | 0 | 5 |

D本批平均时间增加约9.7%、token增加约10.5%、费用增加约9.2%。
配对bootstrap的95%差值区间为：时间[-0.554, +2.649]秒，token[-4,275, +12,182]，
费用[-0.001570, +0.003436]元，均包含零。加上历史对照的时间/缓存混杂，
不能断言这些变化由LSP造成，也没有证据支持效率提高。

辅助验收唯一新增通过的是J6（确认不存在病历向量数据库实现），该题未调用LSP。
因此不能将16/18到17/18解读为LSP解决了额外问题。严格分数仍明显受JSON外额外解释影响。
全部六类修复结果与C一致，帮助摘要P5仍未在预算内修复。

## LSP究竟发挥了什么作用

- **Agent主动请求LSP：0次。** 正式任务没有definition/references调用，不能评价导航对Agent的增益。
  三语言跨文件definition真实预检成功，是独立的可用性证据，不算Agent使用成绩，也未新增references真实验证。
- **真实编辑反馈：5次，均在后续模型请求中出现。** 通过 `changed_files → PostToolUse → LSP → context_feedback` 完整链路，非仅注册hook。
- **实际诊断结果：2次，均为TypeScript。** 记忆修复返回空诊断；网络过滤修复返回诊断，模型收到前三条缺少Node内置模块类型声明的错误。
  完整记录还包含缺少Buffer类型和隐式any等信息。这是源码子集未安装完整依赖时的环境/既有类型问题，未证明本轮逻辑回归被LSP检出。
  两次诊断均未带服务器文档版本号，服务明确标为同步后的未版本化诊断，不宣称强版本一致性。
- **仅初始化状态：3次。** 两次Java、一次Python在默认1.5秒反馈窗口内尚未就绪；模型看到了`initializing`，并未拿到这些文件的有效诊断。
- **资源释放：已记录的5个服务器进程均退出。** 两个Java进程退出码为1，不能解释为自然正常退出或诊断成功；任务结束后的进程清理未留下这些进程。

这轮暴露的优先改进点是：服务器冷启动与短反馈窗口的衔接、稍后诊断重新进入上下文的机制、
真实项目依赖环境完整性，以及Agent何时选择定义/引用工具。
应先解决这些问题，再用少量面向跨文件关系与类型错误的任务验证；本轮没有继续追加测试。
