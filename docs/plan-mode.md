# Plan Mode

[文档导航](README.md) · [使用指南](usage-guide.md)

Web 会话默认直接执行。点击输入框下方的 **Agent** 按钮打开执行方式菜单，开启 **先出方案**，即可先调查项目、审阅方案，再决定是否执行。
主 Agent 可以自行调查，也可通过原生协作委派只读调查；新任务不需要选择旧 Team 模式。
CLI 的 `--planning-mode auto|tasks|todo` 只选择任务记录后端，不提供这里的方案预览与批准流程。

## 使用流程

1. Agent 调查项目，用 `plan` 保存 Markdown 草稿。草稿和模式保存在本地数据库，刷新页面仍可恢复。
2. 主 Agent 用 `plan(action="submit")` 提交方案，结束本轮并等待确认。
3. 在“查看方案”中阅读全文、切换历史版本、复制或下载 Markdown。
4. “修改方案”返回规划；“放弃方案”退出规划；“批准并执行”启动所批准版本。执行时 Agent 根据任务选择直接完成或原生协作。
5. 启动失败时显示原因并保留方案，可以重试或撤回重做。反复点击批准、服务重启恢复都复用同一次启动记录。

取消当前生成会停止运行，已保存的方案不会丢失；取消运行与放弃方案是两个动作。
**只读** 会话可以生成方案，但批准方案不能解除只读权限。需要先退出规划，将执行方式改为 **Agent**，再开启规划并重新提交方案。

## 原生协作中的规划

规划期间可以用 `TaskCreate` / `TaskUpdate` 定义任务，以 `blockedBy` 表达依赖、`metadata.execution` 表达成员执行配置。
调查工作可通过 `delegate_task` 或 `delegate_batch` 交给 `research` / `review` 成员；这些成员只调查并返回报告，不能修改源码、运行任意 Shell 或继续委派。
`implement` / `verify` 任务需要在批准后的执行阶段运行，不能利用恢复入口绕过规划权限。

方案预览保存的是待审阅的 Markdown 版本；当前原生方案没有旧 Team 那种独立的任务快照审批表。
任务要求和状态仍以 Task 系统为准，执行入口会再次校验任务配置、依赖和权限。具体执行路径见 [原生协作指南](collaboration.md)。

## 权限与缓存

Plan Mode 使用一套明确的调查工具：项目读取、搜索、`inspect_project` 环境检查和
`project_diff` 差异查看。任意 Shell、源码写入、未知外部工具和可写子 Agent 均被拦截。
原生协作可以定义任务并执行受限的只读调查，但主 Agent 不能在规划阶段手动领取或完成任务。
限制同时施加在工具目录、调用入口与 Agent 执行检查，模型无法自行批准或退出规划。

普通执行模式不增加规划工具或提示词。规划提醒追加在上下文中，方案正文不反复改写
系统提示词和工具定义。修改草稿保持系统提示词与工具前缀稳定；进入/退出模式会改变
工具集合，可能使这一次请求重新建立缓存。真实供应商的缓存命中率仍需线上观测。

## 数据和执行边界

`planning_sessions` 保存会话模式；`planning_revisions` 保存不可变的已提交版本、
内容哈希、启动状态和执行关联；历史 Team 方案还包含任务快照。审批请求必须携带当前版本的内容哈希。
批准前检查调查文件指纹。文件检查覆盖当前上下文中记录的读取路径（最多 200 个），
不是整个文件系统的锁或完整快照，也不覆盖外部资料、子 Agent 调查的全部内容。

规划调查不要求先初始化 Git，空目录和非 Git 项目也可以生成方案。
批准会启动执行，并不代表所有任务已验证；是否使用受管理的协作目录，以及结果如何写回，由实际执行路径决定。

## 历史 Team 兼容

旧 Team 的规划记录、`TeamPlanSubmit` 与统一方案审批仍保留。通过旧入口创建 Team 时自动进入规划；
继续已有运行中的 Team 不会重新要求规划，当前菜单仅对已有团队显示“历史团队”。
旧流程将方案和任务依赖、范围、验证命令一起提交，批准后不再弹出第二次相同审批。

Team 批准前还会检查任务快照，启动事务再次检查任务，防止准备 Git 期间的任务修改绕过审阅。
旧 Team 规划期间不创建 Git 快照、Worktree 或运行 Worker。批准后，Runtime 会为非 Git 目录初始化本地仓库，
为尚无提交的仓库创建一个空的初始提交；用户文件和暂存区保持原样，再由临时索引
捕获本地内容供 Team 使用。不设置远程、不推送、不要求全局配置 Git 用户名。
已有正常 HEAD 的仓库直接复用；中断后重试不会重复创建初始提交。
Git 未安装、仓库损坏或工作目录不是仓库根目录时仍会提示原因。已有本地快照、集成和交付流程继续复用。
